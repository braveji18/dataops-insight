# SECOM 불량 예측: OpenCrab 논문 기반 변수 선택 파이프라인

`data/uci-secom/uci-secom.csv`(반도체 공정 센서 590개, 타깃 `Pass/Fail`)에 OpenCrab에 등록된
논문 정리 노트(`docs/RF튜닝_고차원선형모형자동화.md`)의 "p≫n 변수 선택 권장 파이프라인"을 적용한
분석입니다.

## 요약

- 학습용 데이터 안에서 nested CV로 평가한 AUC는 **0.739 ± 0.113**입니다.
- 시간상 뒤쪽인 검증용 데이터에서는 **AUC 0.438**(95% CI 0.30–0.57)로, 무작위 예측 수준입니다.
  비교 모델(lasso 0.533, RF 0.535)도 마찬가지입니다.
- 원인은 **시기별 공정 분포 변화(drift)**입니다.
  - 학습 행과 검증 행을 구분하는 분류기의 AUC가 0.992로, 두 시기의 센서 분포가 거의 완전히 다릅니다.
  - 주 모델이 쓰는 센서 32개 중 25개의 분포가 유의하게 바뀌었습니다.
  - 학습 데이터만으로 "과거 학습 → 미래 예측" 순서로 평가해도 AUC가 0.650까지 떨어집니다.
- 결론: 파이프라인은 논문 권고대로 구현했고, 같은 시기 안에서는 비교 모델보다 약간 낫습니다.
  하지만 이 데이터에서는 **변수 선택보다 시간에 따른 분포 변화 대응이 먼저 해결할 문제**입니다.

## 데이터와 분할

| 항목 | 값 |
| --- | --- |
| 원본 | 1,567행 × 센서 590개, 결측 4.5% |
| 타깃 | `Pass/Fail`: -1 양품, 1 불량 → 분석에서는 1 = 불량으로 변환 |
| 학습용 `split/train.csv` | 앞쪽 75%, 1,175행, 불량 80건(6.8%), 2008-07-19 ~ 09-29 |
| 검증용 `split/holdout/valid.csv` | 뒤쪽 25%, 392행, 불량 24건(6.1%), 2008-09-29 ~ 10-17 |

- **시간 순서 분할:** 과거 로트로 학습해 미래 로트를 예측하는 실제 사용 방식과 같게 나눴습니다.
- **날짜 오류:** 이 CSV는 일(day)이 12 이하인 날짜에서 일과 월이 뒤바뀌어 있습니다
  (예: `2008-01-08`은 실제로 8월 1일). 그래서 `Time`으로 정렬하지 않고 파일 행 순서로 나눴습니다.
  날짜를 바로잡으면 파일 행 순서가 시간 순서와 정확히 일치합니다(역행 0건).
- **요청과 다른 점:** 요청은 "p≫n 회귀"였지만, 이 데이터는 **이진 분류**이고 p=590 < n=1,567입니다.
  다만 불량이 104건뿐이라 불량 사례 수에 비해서는 변수가 매우 많습니다. 그래서 노트의 파이프라인을
  분류용으로 옮겨 적용했습니다. SIS, L0Learn, SISSO, SpAM 모두 분류를 지원합니다.

- 결정 임계값은 학습 데이터의 out-of-fold 예측에서 F1이 최대가 되는 값으로 정했습니다.
- 주 모델(`paper_pipeline`)은 평가 전에 미리 정했고, 검증 결과를 보고 모델을 바꾸지 않았습니다.

## 파이프라인

`paper_pipeline` = `Cleaner → SISScreener → TransformGenerator → 희소 로지스틱` ([common.py](common.py))

0. **정리 (Cleaner)**
   - 결측이 50%를 넘는 센서, 상수 센서, 사실상 중복인 센서(|r|>0.999)를 제거합니다(590 → 419개).
   - 남은 센서는 중앙값으로 결측을 채우고 표준화합니다.
1. **스크리닝 (SIS/ISIS)**
   - |corr(x, y)| 상위 k개를 남깁니다.
   - ISIS 옵션: 절반은 상관으로 뽑고, 나머지 절반은 1차 희소 로지스틱의 잔차와의 상관으로 뽑습니다.
   - k ∈ {20, 50, 100}, ISIS 사용 여부는 CV로 선택합니다.
2. **변환 후보**
   - 스크리닝된 센서에 x²와 부호 보존 로그 sign(x)·log(1+|x|)를 추가합니다.
   - 추가 여부 자체를 CV로 선택합니다.
3. **희소 선택**
   - L1/elastic-net 로지스틱을 씁니다(class_weight=balanced).
   - C ∈ {0.01…1}, l1_ratio ∈ {1, 0.5}.
   - L0Learn은 R 패키지라 분석 컨테이너에 없어서, 노트 3단계가 대안으로 명시한 lasso/elastic-net을 썼습니다.
4. **평가**
   - 외부 5-fold × 내부 5-fold nested CV로 평가합니다(탐색 조합 120개).
   - 지표: ROC-AUC(선택 기준), PR-AUC(불균형 보조 지표).

**비교 모델**
- `lasso_all`: 스크리닝과 변환 없이 정리된 센서 419개 전체에 L1 로지스틱
- `rf`: 트리 500개 고정, max_features ∈ {sqrt, 0.2} × min_samples_leaf ∈ {1, 5} 튜닝

## 결과

### 학습 데이터 (nested CV)

| 모델 | nested AUC | 튜닝 결과 그대로의 AUC | nested PR-AUC |
| --- | --- | --- | --- |
| **paper_pipeline** | **0.739 ± 0.113** | 0.784 | **0.226** |
| lasso_all | 0.710 ± 0.096 | 0.756 | 0.188 |
| rf | 0.745 ± 0.087 | 0.779 | 0.223 |

- "튜닝 결과 그대로의 AUC"는 내부 CV에서 가장 좋았던 조합의 점수를 그대로 보고한 값입니다.
  nested 값보다 0.03~0.05 높은데, Bischl et al.이 경고한 낙관 편향이 실제로 나타난 것입니다.
- 최종 설정: k=100, SIS(ISIS 아님), 변환 사용, C=0.03, L1. 계수가 0이 아닌 항은 48개입니다.
- 외부 5개 fold 모두 변환을 사용한 설정이 선택됐습니다.
  - 변환 후보가 들어간 이유는 센서 분포가 치우쳐 있고 이상값이 많기 때문으로 보입니다.
  - 5개 fold 모두에서 선택된 항: `slog(s59)`, `s64²`
  - 4개 fold에서 선택된 항: `slog(s21)`
- 반면 fold마다 선택된 변수 개수(7~36개)와 구성이 크게 달라, 선택 결과는 불안정합니다.

### 검증 데이터 (한 번 평가)

| 모델 | AUC | PR-AUC (기준 0.061) | Brier | 임계값 적용 시 (TP/FN/FP) |
| --- | --- | --- | --- | --- |
| **paper_pipeline** | **0.438** (95% CI 0.30–0.57) | 0.070 | 0.125 | 2 / 22 / 22 |
| lasso_all | 0.533 | 0.115 | 0.131 | 2 / 22 / 24 |
| rf | 0.535 | 0.066 | 0.058 | 0 / 24 / 9 |

세 모델 모두 검증 데이터에서는 무작위 수준입니다.

### 원인 진단 (`03_diagnose.py`)

| 진단 | 결과 |
| --- | --- |
| 학습 데이터 안의 시간 순서 CV AUC (섞은 CV 대비) | paper 0.650 (0.739), lasso 0.579 (0.695), rf 0.603 (0.747) |
| paper 모델의 구간별 시간 순서 CV AUC | 0.54 → 0.80 → 0.79 → 0.63 → **0.48** (마지막 구간) |
| 학습 행과 검증 행 구분 분류기 AUC | **0.992** (두 시기가 거의 완전히 구분됨) |
| 주 모델 사용 센서 중 분포가 바뀐 것 (KS p<0.01) | 32개 중 25개. 예: `s59` 중앙값 1.48 → -0.55, `s468` 124.5 → 234.3 |

1. 행을 섞는 CV는 같은 시기 데이터끼리 보간하기 때문에, 미래 예측 성능을 과대평가합니다.
2. 불량과 관련 있어 보이던 센서들의 분포가 검증 시기에 크게 바뀌어, 학습 시기의 규칙이
   맞지 않게 됐습니다.

## 한계와 다음 단계

- 이 데이터의 핵심 문제는 **분포 변화(drift)**이므로 다음 순서를 권합니다.
  1. **시간 순서 CV로 튜닝과 평가:** 섞은 nested CV 대신 forward-chaining을 쓰면,
     학습 단계에서 현실적인 성능을 볼 수 있습니다.
  2. **분포 변화에 강한 특징:** 원래 값 대신 로트·기간별 기준값 대비 편차나 순위 같은 상대 특징을 씁니다.
     시기 판별 분류기의 중요 센서를 제외하는 것도 검토할 만합니다.
  3. **최근 데이터 가중과 주기적 재학습:** 분포가 바뀌는 시점을 모니터링합니다.
- 검증용 데이터의 불량이 24건뿐이라 AUC 신뢰구간이 넓습니다(0.30–0.57).
- 이번 분석은 요청대로 노트의 권장 파이프라인을 충실히 구현하고 평가하는 데 집중했습니다.
  위 개선안은 검증 결과를 본 뒤의 제안입니다. 적용한다면 새 검증 구간(또는 새 데이터)으로
  다시 평가해야 공정합니다.

## 실행 방법

저장소 루트에서 실행합니다(분석 컨테이너 `lab`, `docs/localcrab-docker.md` 참고).

```bash
docker compose run --rm lab python data/uci-secom/analysis/00_split.py      # 분할
docker compose run --rm lab python data/uci-secom/analysis/01_train.py      # 학습·nested CV (약 10분)
docker compose run --rm lab python data/uci-secom/analysis/02_evaluate.py   # 검증 데이터 평가
docker compose run --rm lab python data/uci-secom/analysis/03_diagnose.py   # 원인 진단
```
