# SECOM 불량 예측 2차 분석: 분포 변화(drift)를 고려한 파이프라인

1차 분석([../analysis/README.md](../analysis/README.md))의 "한계와 다음 단계"를 적용해 다시 분석했습니다.

1. 튜닝과 평가를 **시간 순서 CV**로 수행
2. **분포 변화에 강한 특징:** 과거 기준 대비 상대 편차 특징, 드리프트가 심한 센서 제거
3. **최근 데이터 가중과 재학습 효과** 확인

데이터 분할은 1차와 같습니다(`../split/`: 앞쪽 75% 학습, 뒤쪽 25% 검증).

## 요약

| | 1차 분석 | **2차 분석 (이번)** |
| --- | --- | --- |
| 학습 데이터 내 성능 추정 | 섞은 nested CV AUC 0.739 | **시간 순서 nested CV AUC 0.576** |
| 검증 데이터 AUC | 0.438 (95% CI 0.30–0.57) | **0.567** (95% CI 0.43–0.70) |
| 추정과 실제의 차이 | -0.30 (크게 과대평가) | **-0.01 (거의 일치)** |
| 최종 모델 크기 | 48개 항 | 8개 항 (센서 5개) |
| 검증 데이터 불량 검출 (임계값 적용) | 24건 중 2건, 정밀도 0.08 | 24건 중 4건, 정밀도 0.21 |

- **가장 큰 성과는 평가 방식의 교정입니다.** 시간 순서 CV로 바꾸자 학습 데이터만으로 낸 추정(0.576)이
  검증 결과(0.567)와 맞게 됐습니다. 1차 분석처럼 배포 전에 성능을 과신하는 일이 없어집니다.
- **분포 변화 대응 기법(상대 특징, 드리프트 센서 제거)은 성능을 올리지 못했습니다.**
  최종 모델은 원래 센서 값을 쓰고, 드리프트 필터도 쓰지 않는 설정이 뽑혔습니다.
  상대 특징으로 바꿔도 두 시기를 구분하는 분류기의 AUC는 0.992에서 0.978로 거의 줄지 않았습니다.
  단순한 기준값 이동이 아니라 센서 간 관계 자체가 바뀌는 변화로 보입니다.
- 결론적으로 이 데이터에서 과거 센서 값으로 미래 불량을 예측하는 능력은 **AUC 0.55~0.65 수준으로 약합니다.**
  예측 모델 개선보다 주기적 재학습과 분포 변화 감시가 현실적인 운영 방안입니다.

## 근거 논문 (OpenCrab MCP `ontology_query`로 조회)

| 적용 내용 | 근거 | node_id |
| --- | --- | --- |
| 시간 순서 nested CV | 순차 수집 데이터는 일반 CV 대신 rolling/expanding window로 평가해야 하며, 내부·외부 루프 모두 해당 | `paper-arxiv-2107.05847` |
| 메타 과적합 해석 | 튜닝 결과 점수를 그대로 쓰면 낙관 편향이 생기고, 데이터가 작을수록 심해짐 | `paper-arxiv-2107.05847` §4.4 |
| 상대 특징을 과거 데이터로만 계산 | 시계열 특징은 과거 데이터로만 계산해야 한다는 제약 | `paper-arxiv-2211.12507` |
| 스크리닝·변환·희소 선택 | 1차 분석과 같음 (노트 권장 파이프라인) | `note-81aa83ae2396055b`, `paper-1da5d2d6e08e02f4`, `paper-arxiv-1901.07329`, `paper-arxiv-1803.01454` |
| RF 트리 수 고정 | 트리 수는 튜닝하지 않고 크게 고정 | `paper-arxiv-1705.05654` |

## 검증 데이터 격리

| 스크립트 | 읽는 파일 | 하는 일 |
| --- | --- | --- |
| `01_train.py` | `../split/train.csv`**만** | 특징 생성, 시간 순서 nested CV, 제거 실험, 최종 모델 저장 |
| `02_evaluate.py` | `final_model.pkl`, 학습·검증 **센서 값**, 검증 라벨 | 한 번만 평가. 적합·튜닝 없음 |

- **상대 특징은 과거 방향으로만 계산합니다.**
  - 각 행의 특징은 그 행 이전 로트들의 센서 값만으로 만듭니다. 앞부분 500행만으로 계산해도 값이 같은 것을 확인했습니다.
  - 그래서 검증 로트의 특징을 만들 때는 직전 로트들(학습 구간 끝과 앞선 검증 로트)의 **센서 값**을 씁니다. 실제 운영에서 쓸 수 있는 정보와 같고, 라벨은 쓰지 않습니다.
- 드리프트 필터와 최근 가중치는 `fit()` 안에서 학습 fold의 행만으로 계산합니다.
- 결정 임계값은 학습 데이터의 시간 순서 예측(블록마다 재학습)에서 F1이 최대가 되는 값입니다.

**주의 (검증 데이터 재사용):** 이 검증 데이터는 1차 분석에서 이미 한 번 평가에 썼고, 이번 설계는 그때의
진단 결과를 보고 정했습니다. 따라서 이번 검증 수치는 완전히 새로운 데이터에서 얻은 값이 아닙니다.
그래서 학습 데이터만으로 낸 시간 순서 nested CV 추정(0.576)을 **주 지표**로 삼았고, 검증 결과는 그 추정이
맞는지 확인하는 용도로만 해석합니다.

## 파이프라인 ([pipeline01.py](pipeline01.py), [01_train.py](01_train.py))

```text
[센서 590개] ─ build_features (과거 로트 기준 상대 특징 590개 추가, 라벨 미사용)
   └ ColumnPicker(raw | rel | both)
     └ Cleaner (결측 50% 초과·상수·중복 센서 제거, 중앙값 대체, 표준화)   ← 1차와 같음
       └ DriftFilter(max_rho)  학습 fold 안에서 |시간과의 순위상관| > max_rho인 특징 제거
         └ SISScreener(k)      ← 1차와 같음
           └ TransformGenerator(x², 부호 보존 로그) ← 1차와 같음
             └ RecencyWeighted(L1 로지스틱, halflife)  최근 로트일수록 큰 표본 가중치
```

- **상대 특징:** `r_s = (x_t − 직전 100로트 중앙값) / 직전 100로트 IQR`. 과거 30로트 미만인 행은 결측으로 두고 대체합니다.
- **최근 가중:** 가중치 = 0.5^(나이/halflife). 나이는 학습 구간의 가장 최근 행이 0, 가장 오래된 행이 1입니다.
- **탐색 범위 (216개 조합):**
  - mode ∈ {raw, rel, both}
  - max_rho ∈ {없음, 0.3}
  - k ∈ {20, 50, 100}
  - 변환 사용 여부
  - halflife ∈ {없음, 0.5}
  - C ∈ {0.01, 0.03, 0.1}
- **평가 방식:**
  - 외부: 확장 윈도우 4블록 × 176행. 학습 구간은 471, 647, 823, 999행입니다.
  - 내부: TimeSeriesSplit(3). 섞기는 어디에도 쓰지 않습니다.
- **주 지표:** 외부 블록마다 불량이 3~8건뿐이라 블록별 AUC는 불안정합니다. 그래서 4개 블록의 예측 704행(불량 22건)을 모두 모아 계산한 AUC를 주 지표로 씁니다.
- **비교 모델:**
  - `rf_drift`: 트리 500개 고정, mode·드리프트 필터·halflife만 탐색
  - `prev_pipeline`: 1차 분석의 최종 설정을 고정한 채 새 평가 방식으로 다시 채점

## 결과

### 학습 데이터 (시간 순서 평가, 예측을 모아 계산한 AUC. 기준 불량률 0.031)

| --- | --- | --- | --- | --- |
| **drift_aware** | **0.576** (PR-AUC 0.105) | 0.645 | 0.620 | 0.500 (상수 예측) |
| rf_drift | 0.565 (PR-AUC 0.040) | 0.645 | 0.632 | 0.615 |
| prev_pipeline (1차 설정 고정) | — | — | 0.629 (PR-AUC 0.157) | — |

**블록별로 선택된 설정 (drift_aware)**

| 블록 | mode | halflife | k |
| --- | --- | --- | --- |
| 0 | rel | 0.5 | 100 |

| 2 | both | 0.5 | 50 |

선택이 블록마다 바뀝니다. 내부 검증 구간의 불량이 몇 건뿐이라, 설정 차이가 잡음에 묻힙니다.

- **최종 설정:** raw, 드리프트 필터 없음, k=20, 변환 사용, halflife=0.5, C=0.03
- **최종 모델의 항 8개:**

  - `s129²` (−0.17), `s129` (+0.12), `slog(s129)` (+0.10)
  - `slog(s21)` (+0.17)
  - `s103` (+0.10), `s103²` (+0.06)
  - `slog(s79)` (+0.01)
  - `s59`와 `s21`은 1차 분석에서도 거의 모든 fold에서 선택된 센서입니다(`slog(s59)` 5/5, `slog(s21)` 4/5).

**제거 실험 (최종 설정에서 한 요소만 끄기, 블록마다 재학습)**

| 끈 요소 | AUC |
| --- | --- |
| 최근 가중 끄기 | 0.646 (끄기 전 0.620) |
| 상대 특징, 드리프트 필터 | 최종 설정에서 이미 꺼져 있음 |

**재학습 효과**
- drift_aware 설정은 처음 471행만으로 학습하면 계수가 모두 0이 되어 쓸모가 없습니다(AUC 0.500).
  블록마다 재학습하면 0.620입니다.
- RF는 한 번만 학습해도 0.615, 재학습하면 0.632입니다.
- 재학습은 도움이 되지만 효과 크기는 작습니다.

## 해석

1. **평가 방식이 가장 중요했습니다.**
   - 학습 추정과 검증 결과의 차이가 1차 분석의 0.30에서 0.01로 줄었습니다.
   - 1차 분석은 행을 섞는 CV 때문에 같은 시기 안에서 보간한 성능을 미래 성능으로 착각한 경우였습니다.
2. **분포 변화 대응 기법은 효과가 없었습니다.**
   - 상대 특징과 드리프트 필터가 선택되지 않았고, 최근 가중은 제거 실험에서 오히려 약간 손해였습니다.
   - 학습 기간(2008-07 ~ 09) 안에서 불량률이 13%에서 1~6%로 바뀌는 등, 공정 상태가 크게 바뀝니다.
   - 반면 튜닝에 쓸 수 있는 불량 사례는 너무 적습니다.
3. **튜닝이 잡음을 따라갑니다(메타 과적합).**
   - 튜닝 결과 그대로의 AUC(0.645)가 nested 추정(0.576)보다 높습니다.
   - 1차 분석의 고정 설정을 그대로 써도(0.629) 튜닝한 경우보다 낫습니다.
   - 이 규모의 데이터에서는 탐색 범위를 넓히는 것보다 설정을 단순하게 고정하는 편이 안전합니다.

## 권장 운영 방안

- **모델은 작고 단순하게:** 이번 최종 모델은 센서 5개입니다. 불량과 관련 있을 수 있는 센서 후보
  (`s59`, `s21`, `s129`, `s103`)로 해석하고, 공정 엔지니어 검토에 쓰는 것이 적절합니다.
- **분포 변화 감시:** `02_evaluate.py`의 두 시기 구분 AUC와 같은 라벨 없는 지표를 주기적으로 계산합니다.
  급변하면 재학습하거나 모델을 신뢰하지 않도록 경보를 냅니다.
- **데이터 확보:** 불량 사례가 더 모여야 시간 순서 평가에서 설정 비교가 의미를 가집니다.
  공정 단계나 장비 정보 같은 추가 변수도 필요합니다.
- **새 검증 데이터 필요:** 이 분할의 검증 데이터는 두 번 쓰였습니다. 모델을 바꿀 때마다 새 기간 데이터로 평가해야 합니다.
