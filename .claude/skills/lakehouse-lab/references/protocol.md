# 비교 측정 프로토콜

측정할 때마다 조건이 달라지면 숫자를 신뢰할 수 없다. 여기 적힌 규칙을 지키지 않은 수치는 `docs/`에 인용하지 않는다.

## 0. 이 랩에서 할 수 있는 것과 없는 것

| | 가능 | 근거 |
|---|---|---|
| 기능 동등성 확인 | ✅ | 같은 Iceberg 테이블, 같은 SQL |
| 실행 계획/푸시다운 확인 | ✅ | 양쪽 EXPLAIN, 스캔 행 수 |
| 에러·경계 동작 확인 | ✅ | 타입 변환, NULL, 시간대, 정밀도 |
| **같은 호스트에서의 상대 시간 비교** | △ | 방향성만. 배수는 참고치 |
| **운영 환경 성능 예측** | ❌ | 1워커/1BE, 컨테이너 자원 제약, arm64 SIMD 경로 차이 |

성능 결론을 쓸 때는 반드시 "이 랩 조건에서"라는 한정을 붙인다.

## 1. 측정 절차 (bench.sh 가 강제하는 것)

- **warm-up 1회 + 측정 3회, 중앙값**. 첫 실행은 메타데이터 로딩·JIT·캐시 채우기가 섞여 있어 버린다.
- **오버헤드 기준선**: 매 측정마다 각 엔진에 `SELECT 1`을 던져 CLI/접속 왕복시간을 함께 기록한다. 100ms대 쿼리는 이 값과 같은 자릿수라 그대로 비교하면 안 된다.
- **호스트 지문 기록**: OS/arch/Docker CPU·메모리/이미지 digest가 결과 JSON에 항상 박힌다. 다른 머신 결과와 섞어 비교하지 않기 위한 안전장치다.

## 2. 캐시 통제

두 엔진의 캐시 구조가 다르다는 것 자체가 비교 대상(plan/01 B-3)이므로, **끄고 재는 것이 항상 옳은 게 아니다**. 목적에 따라 명시적으로 고른다.

| 목적 | 설정 | 방법 |
|---|---|---|
| 순수 스캔·연산 성능 | 캐시 OFF | SR: `SET enable_scan_datacache = false;` / Trino: 별도 결과 캐시 없음 |
| 반복 쿼리 실사용 성능 | 캐시 ON (기본) | 워밍업을 3회로 늘려 캐시를 채운 뒤 측정 |
| 캐시 이득 자체를 측정 | 둘 다 | 같은 쿼리를 OFF/ON 각각 측정해 비율 보고 |

어느 쪽으로 쟀는지 결과에 반드시 적는다.

## 3. 통계(ANALYZE)

옵티마이저 비교(plan/01 A-2)에서 통계 유무는 결과를 뒤집는다.

- `bin/seed.sh` 는 적재 후 **양쪽 모두** 통계를 수집한다 (Trino `ANALYZE`, StarRocks `ANALYZE TABLE`).
- 통계 수집 주체가 다르다는 점(Trino=커넥터 위임, StarRocks=엔진이 직접 수집)이 비교 소재다. 통계 없는 상태의 플랜을 보고 싶다면 `seed.sh --force` 후 ANALYZE를 건너뛴 상태를 따로 만들고, 그 사실을 결과에 적는다.

## 4. 기능 검증(functional probe)의 기록 형식

성능이 아니라 "동작하는가"를 확인한 경우, 다음을 남긴다.

```markdown
### 주장
<docs/ 에 쓰려는 문장 또는 plan/01 의 확인할 질문>

### 판별 쿼리
```sql
-- 이 쿼리가 왜 주장을 판별하는지 한 줄
SELECT ...
```

### 결과
| 엔진 | 결과 | 비고 |
|---|---|---|
| Trino 483 | ... | |
| StarRocks 4.0.14 | ... | |

### 판정
동등 / Trino 우위 / StarRocks 우위 / 한쪽만 지원 / 판별 실패(이유)

### 조건
profile=functional, TPC-H SF0.01, host=darwin/arm64, 캐시=기본값
```

`docs/evidence/<축>/<날짜>-<probe>.md` 에 저장하고, `docs/` 본문에서 이 파일을 링크한다.
코드 인용(`works/<engine>/path:line`)과 런타임 증거가 같은 문서에서 만나야 주장이 검증 가능해진다.

## 5. 하면 안 되는 것

- 한쪽 엔진에만 유리한 SQL로 비교하기 (예: StarRocks 네이티브 테이블 vs Trino Iceberg — 이건 저장 계층이 다른 것이지 엔진 비교가 아니다)
- 워커 수가 다른 상태에서 비교하기 (Trino worker 1 : StarRocks BE 1 을 유지할 것)
- `perf` 프로파일 없이 잰 수치를 성능 결론으로 쓰기
- 결과 JSON 없이 대화에서 본 숫자를 `docs/`에 옮기기
